Architecture design options
When designing an agentic system, you have to decide on the best structure. Below are two common options for the company research problem.

Option A: Single agent
A single agent performs all the tasks in a sequence. It would search the company website, then search for people, then analyze the news, one after another.

Pros: This design is simple to build and manage. It uses a single context window, so there is no need to coordinate between different agents.
Cons: This approach is slow because tasks cannot run at the same time. A single agent is responsible for everything, which can make the workflow long and inefficient.
Option B: Multi-agent
A multi-agent system uses specialized agents that work in parallel. An orchestrator agent assigns tasks to each specialized agent, and they all run at the same time.

Pros: This design is much faster because tasks are executed in parallel. Each agent is an expert at its specific job, which can lead to higher-quality results. It is also easier to add new research capabilities by simply adding a new agent.
Cons: This system is more complex to build. It requires careful coordination between agents and a final step to merge their results into a single report.
For the company research task, the multi-agent architecture is the recommended approach because speed and specialized functions are important.

Orchestration pattern: Parallel with merge
This architecture uses an orchestration pattern called parallel with merge.

The Orchestrator agent receives the initial request from the user (e.g., "Research Acme Corp").
It then spawns the three specialized agents—Web Researcher, People Finder, and News Analyst—to run in parallel.
Each specialized agent completes its task and returns its findings.
Finally, the Orchestrator merges the results from all three agents into a single, comprehensive report for the user.
This pattern is effective when sub-tasks can be performed independently and you need to get the final result as quickly as possible.

Key terms
Agentic system

Non-agentic system: A system that provides a single response to a single prompt without the ability to use external tools or iterate.

Orchestrator: A central agent in a multi-agent system that coordinates the work of other, more specialized agents.

Summary
Agentic systems are defined by their ability to work autonomously, use tools, and iterate on tasks.
For simple, linear tasks, a single-agent architecture is often sufficient.
For complex tasks that require speed or specialized expertise, a multi-agent architecture is more effective.
The orchestrator pattern is a common way to manage multi-agent systems, where a central agent coordinates specialized agents and compiles their results.
